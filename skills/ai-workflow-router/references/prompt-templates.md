# Prompt Templates

依 router 選出的流程與 context mode，只選一個範本並替換方括號。若 agent 支援對應 skill，可在第一句加入「請使用 `[skill 名稱]`」；不要假設不存在的工具。

## Direct：明確小型修改

```text
請直接處理 [需求]。先確認受影響的 [檔案／模組]，只做必要修改；完成後執行最貼近變更的測試或 lint，回報變更、驗證結果與仍存在的限制。
```

## Direct：先整理規格再實作

```text
請先把 [需求] 整理成精簡 spec：目標、非目標、影響範圍、驗收條件與待確認決策。確認關鍵決策後再實作；沿用既有文件與模式，避免額外重構，並以對應測試驗證。
```

## Compact：同一任務降載

```text
請先整理目前任務的 checkpoint，只保留：目標、硬性約束、已確認決策、已修改檔案、驗證結果、未解風險與下一步。以檔案路徑取代完整舊輸出，清除已消化的 logs／搜尋結果後，再從下一個未完成步驟繼續。
```

## Subagent：隔離探索噪音

```text
請先確認目前是否支援子代理。若支援，委派一個唯讀探索任務：找出 [功能／問題] 的相關模組、現有模式、證據與風險；詳細結果寫入 artifact，只回傳結論、證據路徑、未解問題與下一步。主 agent 保留決策與整合。若不支援，請用相同輸出契約分階段自行完成。
```

## Handoff-reset：跨階段換新 Context

```text
目前工作即將從 [目前階段] 進入 [下一階段]。請建立可讓新 context 直接接手的 handoff：目標、範圍／非範圍、硬性約束、已確認與已否決決策、變更檔案、驗證命令與結果、未解風險、下一個具體動作。不要附完整對話與重複 tool output；以 artifact 路徑提供細節。
```

## Fresh-review：獨立審查

```text
請以乾淨的 reviewer context 檢查 [變更／diff] 是否符合 [需求或 spec]。輸入只包含需求、必要決策、變更範圍、diff 與測試結果；檢查正確性、回歸風險、邊界條件與測試缺口，只列有具體證據的問題。若不能使用獨立 context，請明確切換 reviewer 視角並避免沿用實作者結論。
```

## 通用 Context-aware 路由

```text
請評估本任務的複雜度、目前 context 壓力與可用 agent 機制，再建議最小工作流。主 context 只保留目標、約束、決策、目前狀態與驗證證據；大量探索或工具輸出若可隔離，使用子代理並採 artifact-first 交接。壓力升高時先建立 checkpoint，再選擇 compact 或 handoff-reset；小任務不要自動堆疊 spec、tickets、TDD、多代理與多輪 review。
```
